# Open Wearables Audit — 2026-09-01

## Findings

### Ghost Users (371 OW users, all NULL identity)

Every user in the OW database has `email=NULL`, `external_user_id=NULL`. Only 56 of 121
HolisticOS `user_profiles` rows have `ow_user_id` set. That leaves ~315 orphaned OW users
with no link to any HOS account.

**Root cause — three compounding bugs in `register_user()`:**

1. `POST /users` was called with an empty body `{}` — `external_user_id` was never stored,
   so OW has no way to recognise a re-registration attempt from the same HOS user.
2. `_claim_ow_user_id()` returns `None` when the `user_profiles` row doesn't exist yet.
   `register_user()` returned `True` in that case, so Flutter received HTTP 200, re-read
   `user_profiles.ow_user_id`, saw NULL again, and re-entered the loop on the next app open
   — creating a new ghost each time.
3. No pre-flight check: before creating a new OW user, the code never looked for an
   existing one by `external_user_id`. Every failed claim left an orphaned record that
   would never be reclaimed.

**Fix applied (2026-09-01):**
- `register_user()` now passes `external_user_id=hos_user_id` on create.
- Added `_find_by_external_id()` — before creating, look up any existing OW user whose
  `external_user_id` matches the HOS UUID and claim that record instead.
- `register_user()` now returns `False` (→ HTTP 503) when `_claim_ow_user_id` returns
  `None` (user_profiles row missing), so Flutter knows registration is incomplete and
  retries rather than marking OW as initialised with a NULL id.

### Dashboard Search Doesn't Match UUID

`UserQueryParams.search` only filters `email`, `first_name`, `last_name`. Pasting an OW
UUID (or a HOS UUID) into the search box returns 0 results even when the user exists.
Fixed in `user_repository.py`: `cast(self.model.id, String)` added to the OR clause.

### Refresh Token Bloat

2,313 SDK refresh tokens — every one of them `last_used_at=NULL`. The Flutter SDK calls
`ensureActiveForUser()` on every app open, which issues a fresh token each time; it never
calls the refresh endpoint. Revoked tokens are never pruned.
Mitigation: add a weekly `DELETE FROM public.refresh_token WHERE revoked_at IS NOT NULL
AND revoked_at < now() - interval '7 days'` via Supabase scheduled function.

## Cleanup SQL (run after fix is deployed)

Delete orphaned OW users that have no `external_user_id`, no data sources, and no
connections. Run the `SELECT` first to verify count before deleting.

```sql
-- Count first
SELECT count(*)
FROM public.user
WHERE external_user_id IS NULL
  AND email IS NULL
  AND id NOT IN (SELECT DISTINCT user_id FROM public.data_source)
  AND id NOT IN (SELECT DISTINCT user_id FROM public.user_connection);

-- Then delete
DELETE FROM public.user
WHERE external_user_id IS NULL
  AND email IS NULL
  AND id NOT IN (SELECT DISTINCT user_id FROM public.data_source)
  AND id NOT IN (SELECT DISTINCT user_id FROM public.user_connection);
```
